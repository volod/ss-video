## Implementation

Internal Pydantic models in `src/selfsuvis/pipeline/analysis4d/` (`extra=forbid`) cover tracks, graph deltas, proposals, timelines, QA, masks, geometry, gaps, the manifest, evaluation truth, and the benchmark report. The timeline example in the specification round-trips. These schemas are not an ss-common ODCS contract and nothing is published to fusion-rt.

`AnalysisStore` appends JSONL and replaces `timeline.json` or `manifest.json` only when `supersedes_sha256` matches the previous digest. The previous file is copied under `history/`. `validate_bundle` rejects dangling ids, mixed coordinate frames, invalid intervals, unversioned output, supersession cycles, and accepted edges that disagree with stored geometry. Skipped frames require a gap record. Accepted metric locations require `metric_scale` `metric`.

`migrate_video.py` adds `analysis4d_runs`, `analysis4d_events`, `analysis4d_edges`, and `analysis4d_qa` on the video database, keyed by mission and by the manifest sha256. `pipeline/storage/analysis4d.py` replaces one run's query rows. `worker/artifacts.py` `analysis_artifact_dir` resolves `$DATA_DIR/analysis/<mission_id>/4d`.

Corpus `analysis4d-v1` is generated by `pipeline/analysis4d/corpus.py` and pinned under `tests/assets/analysis4d/`. It covers camera cuts, long occlusion, crowded repeated objects, moving camera, weak calibration, relative depth, a contradictory proposal, and an empty scene. `truth.json` is evaluation-only and is not listed in the runtime manifest. No model provenance is attached; every mission records `models_missing`.

`python -m selfsuvis.pipeline.analysis4d.benchmark` writes `$DATA_DIR/analysis/_benchmark/report.json`. `passed` means contract integrity: every specification metric and stage field is present, required conditions are covered, and the empty timeline is valid. It does not apply the later quality thresholds (relation precision >= 0.90, verifier false acceptance <= 0.02, or real-time factor <= 1.0 on a 15-minute stream). HOTA and IDF1 are single-threshold fixture scores, not TrackEval. `peak_vram_bytes` is this process's GPU memory; the runner loads no CUDA model, so the measured value is 0.
